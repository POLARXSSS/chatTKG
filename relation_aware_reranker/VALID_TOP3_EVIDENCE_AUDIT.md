# ICEWS14 开发集：正确答案 vs 前三错误候选的成对证据审计

本审计固定使用 P1 `wide_h128_query_pairwise` 的 seed 13 检查点、原 `512/128/640` 候选上限、完整 ICEWS14 `valid`。它是**失败模式的描述性审计**，不是五类原因的因果分解，也没有用 `test` 选择阈值或调参。此次 GitHub 发布仅包含本 Markdown，不包含数据、模型、审计脚本或逐对记录；以下统计来自本地完整开发集复算，全部 27,646 条名次与冻结归档逐项一致。原始机器可读主报告 SHA-256：`8bb72f71b9a4787253193fbc4af66232a2bae422aa5a68f16b10403cfc2899b1`；逐对记录 SHA-256：`621a1ad116f989d93bd2bbce343e22775df9fd03b9b1605ec3d23622cf91cd87`。

## 协议与分母

- 13,823 条原始 valid 四元组及逆关系，共 **27,646 条定向事实**、24,395 个 `(s,r,t)` 分组查询。历史只含 train 和严格早于查询日的 valid；同日其他已标注答案从错误候选中排除，并在 filtered rank 中过滤。
- 重算的全部名次及覆盖率与既有冻结 valid 归档**逐项完全相同**。答案在候选池内 22,433 条，缺席 5,213 条；后者不能通过同池重排修复。
- 候选内第一名正确 9,599 条；**12,834 条**答案在池内但 filtered rank > 1，是下表统一分母。其内第 2–3 名 3,889 条，第 4–10 名 2,457 条，第 10 名之后 6,488 条。每条失败事实比较分数最高的前三个**非同日已标注答案**；38,436 个成对记录中，31,907 对分数高于或与正确答案打平，只有这些对进入机制计数。

## 五类证据模式：非互斥，不能加总

| 证据模式 | 失败事实数 / 12,834 | 操作定义与局限 |
| --- | ---: | --- |
| 旧三元组复制 | **8,710（67.87%）** | 前三竞争者之一的可见 `(s,r,o)` 精确历史新近度分数高于真答案；其中 5,082 条是错误候选有可见精确历史、答案没有。表明历史复制偏向，并不能单独证明复制导致失败。 |
| 规则分数饱和 | **2,696（21.01%）** | 真、假候选的原始 TLogic Noisy-OR 分数都 ≥0.99；阈值放宽至 0.95 为 3,827 条。接近 1 的规则分数不再充分区分当日客体。 |
| 陈旧证据 | **7,371（57.43%）** | 错误候选的可见精确三元组历史或最年轻规则路径距查询日 >30 天；精确历史 6,248 条，规则路径 3,883 条，二者有交集。仅 1,632 条出现“错误精确历史比答案的精确历史更旧仍领先”，1,998 条出现相应的更旧规则路径仍领先。**证据旧不等于现实事实已经失效。** |
| 同类实体竞争 | **147（1.15%）** 为同角色名称；**3,236（25.21%）** 为结构相似代理 | 严格名称代理要求两实体都形如 `ROLE_(SCOPE)` 且 `ROLE` 相同；仅 6,535/31,907 个竞争对的双方名称可按此模板解析，因此 147 是明显低估。补充的训练期关系分布余弦相似度 ≥0.8、双方各至少 10 条训练事件，命中 3,236 条；阈值 0.7/0.9 分别为 5,920/1,096 条。它只是“行为轮廓相似”，不是金标准实体类型。同一 `SCOPE` 的名称代理另命中 2,892 条，不应混称为同类型。 |
| 可能的标签不完整 | **3,951（30.79%）** 仅为弱代理 | 某领先“错误”候选在其后 30 天内的 valid 上成为同一 `(s,r,o)` 的已记录事实；其中 840 条不伴随旧复制模式。后一天发生不等于查询当天已发生，故**真正标签不完整的数量无法由 ICEWS14 单独识别**，不能宣称这 3,951 条就是漏标。 |

“陈旧”与“旧复制”有很大重叠：5,356 条同时具有旧复制和陈旧精确历史；旧复制与规则饱和也有 1,597 条交集。只按上述五个主代理计算，1,261 条失败没有命中任何一个。单独只命中“陈旧／旧复制／规则饱和／未来复现／同角色名称”的事实分别只有 1,473／1,026／350／128／6 条；因此按类别比例直接排因果优先级会误导。

## 错误候选为什么领先

对每条失败事实的**最高分错误候选**，原始 TLogic 分数比正确答案高的有 **11,825/12,834（92.14%）**；原始分数低的仅 350 条（2.73%），近似并列 659 条（5.13%）。这说明最常见情况不是 P1 凭空把一个原始高分答案翻错，而是规则／历史证据原本就强烈偏向了错误候选。P1 对 TLogic 的全量逐事实比较也支持分门槛看：Hits@1 救回 1,191 条、损害 157 条；Hits@3 救回 803 条、损害 434 条；但 Hits@10 救回 845 条、损害 **1,632 条**。所以 Hits@1 的主问题是基础证据难以区分当天客体，而 Hits@10 还叠加了后排序把答案挤出前十的问题。

成对例子只说明模式，不是因果验证：

- **复制压过新客体：** 2014-09-20，`Abdullah_Abdullah — Make_a_visit — Foreign_Affairs_(United_States)` 的正确答案排第 8；`Ashraf_Ghani_Ahmadzai` 作为错误候选排在前，其同一三元组 66 天前出现过，TLogic 分数 0.99966，真答案 0.34518。错误候选的最高规则路径却仅 2 天前，说明“旧三元组”与“新路径”可能共同抬分，不能单因归咎复制。
- **饱和仍需细分：** 2014-09-20，`Citizen_(Australia) — _Make_an_appeal_or_request — Police_(Australia)` 的真、假候选 TLogic 分数均约 0.99999；`Lawyer/Attorney_(Australia)` 以 P1 分数 1.182 压过真答案 1.168。两者非常接近的规则分数没有提供足够的当日辨别力。
- **旧路径与同地域：** 2014-09-20，`Akali_Leader — _Praise_or_endorse — Employee_(India)` 排第 5；前列的 `Labor_Union_(India)` 等错误候选共享 `India` 范围，某领先规则路径距当天 123 天。但这些对象可能属于不同角色，不能凭名称认定同类或过期。
- **同角色名称但客体错位：** 2014-09-20，`Angela_Merkel — Consult — Head_of_Government_(Germany)` 的正确答案排第 64，`Head_of_Government_(Qatar)` 具有同一角色模板且排在前；后者还有更强的 TLogic 证据和 3 天前精确历史。相似类型并不意味着应压低它，需要查询关系与具体实体交互信息。

## 解释边界与后续可证伪实验

最值得先验证的是：在**相同候选池、相同开发集协议**下加入能区分当天对象的候选级证据，尤其是关系条件化的新旧证据可靠性、实体／关系交互、规则来源去重或校准；同时以 Hits@10 不退化作为约束。旧证据惩罚不能一刀切，因为有些旧三元组确实会重复发生。应分开消融“校准原始规则／历史分数”和“只改 P1 重排”，并按未重复事实、排名 2–3／4–10／>10 分层；测试集不再用于选择阈值。标签缺失与真正实体类型的判断，需要独立事件文本或外部标注，不能由本审计定论。

复算所需的审计脚本、ICEWS14 数据和冻结检查点仍保留在原研究工作区；它们未随本次单文件发布上传。若需独立复核逐对数字，应一并获取这些产物并核对上面的 SHA-256。
